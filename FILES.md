# Vinlotteri — file and function reference

Every file in the project, what it is for, and what each function inside it does.
Generated by reading the source; keep it updated when you add or rename things.

Not covered: `node_modules/`, the build output (`dist/`, `server-dist/`), and
`webint_program/` (an older course project kept only as visual reference, slated
for deletion — see `CLAUDE.md`).

**Shape of the app.** A React + TypeScript single-page app (Vite) with four pages
behind a fixed bottom nav, served in production by an Express + TypeScript server
that also exposes a small JSON API over flat files in `data/`. Writes are gated by
an admin password; reads are open.

## `data/` — the JSON "database"

Each file is owned by exactly one module under `server/store/`. The whole folder is
bind-mounted in Docker, so its contents survive image rebuilds.

| File | Contents |
| --- | --- |
| `wheelNames.json` | `string[]` — the names currently on the wheel. |
| `players.json` | `{ name, timesPlayed, timesWon }[]` — the stats roster. Counters are **stored**; a player's wine collection is **derived** at read time. |
| `wines.json` | `{ id, name, winner, year, location, date, price, keywords, description, img }[]` — the giveaway log. `winner` is the join key that produces a player's collection. |
| `spinLog.json` | `{ winner, at }[]` — append-only history of recorded spins. |
| `payment.json` | `{ amount, phone }` — the admin-editable Vipps details. `null` means unset, so the UI shows its placeholders. |
| `uploads/` | Wine photos uploaded through the app (created on first upload, gitignored). Served at `/uploads/…`. |

## `server/` — Express API and static host

### `server/index.ts`
Wires everything together: middleware, the API routes, the uploaded-image static
route, and (in production) serving the built client. Reads `PASSWORD` from `.env`
via `process.loadEnvFile()`, falling back to the process environment in Docker.

| Function | Purpose |
| --- | --- |
| `isAdmin(req)` | The single gate for every write. Compares the password from the request body or the `x-admin-password` header against `PASSWORD`; returns `false` when no password is configured at all. |
| `todayDDMMYYYY()` | Today as `"dd.mm.yyyy"` — the date format already used throughout `wines.json`. Used when a new wine arrives without a date. |
| `currentStats()` | Reads players + wines and joins them via `computeStats()`; the exact shape the UI consumes. |

**Endpoints**

| Method + path | Auth | What it does |
| --- | --- | --- |
| `GET /api/wheel-names` | open | The wheel pool. |
| `GET /api/wines` | open | The full giveaway log. |
| `GET /api/payment` | open | The Vipps amount/number. |
| `GET /api/players` | open | Roster with each player's derived collection. |
| `POST /api/admin/login` | — | Validates a password so the client can enter admin mode. `200` or `401`. |
| `POST /api/spins/record` | admin | Records one round: `timesPlayed +1` for everyone on the wheel, `timesWon +1` for the winner, plus a `spinLog.json` entry. The only writer of those counters. |
| `PUT /api/payment` | admin | Stores the amount (positive number or `null`) and Vipps number (validated against a digits/`+`/space pattern). |
| `POST /api/wines` | admin | Logs a wine. Assigns the id and today's date, splits comma-separated keywords, and saves an attached base64 photo. `413` if the image is too large. |
| `POST /api/wheel-names` | admin | Adds a name to the wheel **and** creates a zeroed stats row if the person is new. `409` if the name is already on the wheel. |
| `DELETE /api/wheel-names/:name` | admin | Removes a name from the wheel only — the stats row, counters and won wines are deliberately left alone. |
| `GET /uploads/*` | open | Uploaded wine photos, served straight from `data/uploads/`. Registered before the SPA catch-all so these URLs never return `index.html`. |
| `GET *` | open | In production only: serves `dist/index.html` so client-side routing works. |

### `server/store/paths.ts`
Resolves where the JSON files live: `DATA_DIR` (overridable by the env var of the
same name, which is how the tests and Docker point elsewhere) defaulting to `./data`.

| Function | Purpose |
| --- | --- |
| `dataFile(name)` | Absolute path to one file inside the data directory. |

### `server/store/players.ts`
Owns `players.json`. Exports the `PlayerRecord` (stored) and `PlayerStats`
(record + derived `collection`) types.

| Function | Purpose |
| --- | --- |
| `readPlayerRecords()` | *(private)* Parses `players.json`. |
| `writePlayerRecords(players)` | *(private)* Serialises the roster back to disk. |
| `computeStats(players, wines)` | Attaches each player's collection by filtering wines on `winner === name`. Pure — no I/O. |
| `readPlayers()` | Public read of the stored roster. |
| `findOrCreate(players, name)` | *(private)* Returns a player's record, appending a zeroed one if the name is unknown. |
| `recordRound(names, winner)` | Bumps `timesPlayed` for everyone in `names` and `timesWon` for the winner, then persists. |
| `addPlayer(name)` | Appends a zeroed row unless the name already exists (case-insensitive), so re-adding someone keeps their counters. |

### `server/store/wheelNames.ts`
Owns `wheelNames.json`.

| Function | Purpose |
| --- | --- |
| `readWheelNames()` | The current pool. |
| `writeWheelNames(names)` | *(private)* Persists the pool. |
| `wheelNameExists(name)` | Case-insensitive membership test, used for the duplicate `409`. |
| `addWheelName(name)` | Appends unless an equal name (ignoring case) is already there. |
| `removeWheelName(name)` | Drops every case-insensitive match. Touches nothing else — stats survive. |

### `server/store/wines.ts`
Owns `wines.json`. Exports the `Wine` type and `NewWine` (`Wine` without `id`).

| Function | Purpose |
| --- | --- |
| `readWines()` | The whole giveaway log. |
| `addWine(input)` | Appends one wine with the next free id (max + 1) and returns it. Because collections are derived from `winner`, this single write makes the bottle appear both in that player's collection and in the general list. |

### `server/store/spinLog.ts`
Owns `spinLog.json`, the append-only history. Exports the `SpinEntry` type.

| Function | Purpose |
| --- | --- |
| `readSpinLog()` | *(private)* Parses the log, returning `[]` if it is missing or unreadable. |
| `appendSpin(winner)` | Appends `{ winner, at: <ISO timestamp> }`. |

### `server/store/payment.ts`
Owns `payment.json`. Exports the `PaymentSettings` type.

| Function | Purpose |
| --- | --- |
| `readPayment()` | Returns the stored amount/number, or `{ amount: null, phone: null }` when the file is missing or malformed — so a fresh install shows placeholders instead of erroring. |
| `writePayment(settings)` | Persists both values. |

### `server/store/uploads.ts`
Owns `data/uploads/`. Exports `UPLOAD_DIR`, `MAX_IMAGE_BYTES` (4 MB) and
`ImageTooLargeError`.

| Function | Purpose |
| --- | --- |
| `slug(name)` | *(private)* Filename-safe stem from a wine name (`"Barolo Riserva"` → `barolo-riserva`). |
| `saveWineImage(name, base64, ext)` | Decodes the image, rejects anything over the size cap, whitelists the extension, writes `<slug>-<timestamp>.<ext>` and returns its `/uploads/…` URL. Nothing from the client reaches the filesystem verbatim. |

## `src/` — the React client

### Entry and shell

#### `src/main.tsx`
Mounts the app into `#root`, wrapped in `StrictMode` → `I18nProvider` →
`AdminProvider`. Imports the global stylesheet. Throws if `#root` is missing.

#### `src/App.tsx`
The shell. Holds the current `View` — one of the four pages, or a `player`
sub-view for a single person's collection — and decides what the header shows,
which pages are vertically centred with the flanking cats, and where the pouring
backdrop appears (Betaling only).

| Export | Purpose |
| --- | --- |
| `Page` | `'payment' \| 'wheel' \| 'wines' \| 'stats'` — the nav's four destinations. |
| `App()` | Renders header (title, mascots, hidden admin unlock), the active page, the sponsor tag and the bottom nav. |

### Pages (`src/pages/`)

#### `PaymentPage.tsx`
Left page: the Vipps instruction, centred. The whole box is a link that hands over
to the Vipps app on touch devices. In admin mode an editor for amount and number
appears below.

| Function | Purpose |
| --- | --- |
| `vippsHref()` | `vipps://` when the pointer is coarse (a phone with the app), otherwise `https://vipps.no`. |
| `PaymentPage()` | Loads the stored settings, falls back to the `X`/`Y` placeholders while unset, and renders the box + the admin form. |
| `handleSave(e)` | *(inner)* PUTs the amount/number and reflects a saved/failed status. |

#### `WheelPage.tsx`
Middle page and the default view: the wheel itself, the winner announcement with
full-screen confetti, and — in admin mode — the participant editor.

| Function | Purpose |
| --- | --- |
| `WheelPage()` | Loads the wheel names and owns the winner, spinning, and editor state. |
| `handleWinner(name)` | *(inner)* Shows the winner and, only in admin mode, posts the result so the stats are updated. Non-admin spins are purely visual. |
| `handleAdd(e)` | *(inner)* Adds a participant; shows a duplicate/failure message when the server refuses. |
| `handleRemove(name)` | *(inner)* Confirms, then removes the name from the wheel (stats untouched). |

The editor is disabled while the wheel is turning, since changing the list mid-spin
would move the segment the pointer is travelling toward.

#### `WineListPage.tsx`
The general "Viner" page: fetches every wine and hands it to `WineGrid`.

| Function | Purpose |
| --- | --- |
| `WineListPage()` | Loads `wines.json` through the API and renders the grid. |

#### `StatsPage.tsx`
The table of everyone who has played. Read-only — the roster is edited on the
wheel page. Names are plain bold text; the "Se X viner" link is the only way into
a player's collection.

| Function | Purpose |
| --- | --- |
| `StatsPage({ onViewPlayer })` | Loads the roster with derived collections and renders the table. |

#### `PlayerWinesPage.tsx`
One player's collection, reached from the stats table. In admin mode it also
offers "+ Legg til vin".

| Function | Purpose |
| --- | --- |
| `PlayerWinesPage({ name, onBack })` | Finds the player in the roster and renders their wines. |
| `handleSaved(wine)` | *(inner)* Closes the form and appends the new bottle to the visible collection without a refetch. |

### Components (`src/components/`)

#### `Wheel.tsx`
The wheel itself: an SVG rendered generically from a names array of **any** length,
spun by a CSS transform transition.

| Symbol | Purpose |
| --- | --- |
| `SEGMENT_COLORS`, `R`, `EXTRA_TURNS`, `SPIN_MS` | Alternating segment colours, the SVG radius, how many full turns precede the landing, and the spin duration. |
| `polar(angleDeg, radius)` | Converts an angle measured clockwise from 12 o'clock (where the pointer sits) into SVG x/y. |
| `Wheel({ names, onWinner, onSpinStart })` | Draws the segments, the labels and the pointer. |
| `spin()` | *(inner)* Picks a winner uniformly over **all** names — past winners included — then computes the rotation that lands that segment under the pointer. |
| `handleTransitionEnd()` | *(inner)* Fires `onWinner` once the animation actually finishes. |

#### `WineCard.tsx`
One card in the grid: name centred at the top, then year/place/date, image, winner,
keywords and description. Clicking it opens the modal.

#### `WineGrid.tsx`
The responsive card grid plus the shared detail modal; shows `emptyText` when there
is nothing to list. Used by both the general list and a player's collection.

#### `WineModal.tsx`
The centred detail card over a backdrop, mirroring the reference project's
interaction. Closes on backdrop click, the ✕, or Escape.

#### `AddWineForm.tsx`
The admin-only "log a wine" modal, opened from a player's page. The winner is fixed
to that player.

| Function | Purpose |
| --- | --- |
| `fileToBase64(file)` | Reads a picked file and strips the `data:…;base64,` prefix — the server stores raw base64. |
| `isoToDisplayDate(iso)` | `"2026-08-28"` (what `<input type="date">` gives) → `"28.08.2026"` (what `wines.json` uses). |
| `todayIso()` | Today in the date input's format, used as the default. |
| `AddWineForm({ winner, onClose, onSaved })` | The form: name, year, date, place, price, keywords, description and a click-or-drop image picker with a live preview. |
| `handleDrop(e)` | *(inner)* Accepts a dragged image file. |
| `handleSubmit(e)` | *(inner)* Posts the wine (with the photo, if any) and reports "too large"/"failed". |

#### `AdminUnlock.tsx`
The way into admin mode: a **fully transparent** button in the header's right
corner (no glyph, no tooltip, no hover hint) that reveals a password field. Once
unlocked it shows a 🔓 status; leaving admin mode is done from the ADMIN badge on
the wheel page.

| Function | Purpose |
| --- | --- |
| `AdminUnlock()` | Renders the hidden button, the password form, or the unlocked status. |
| `handleSubmit(e)` | *(inner)* Validates the password against the server and shows an error state on failure. |

#### `BottomNav.tsx`
The fixed four-item nav (Betaling · Hjulet · Viner · Statistikk), highlighting the
active page.

#### `SponsorTag.tsx`
The discreet "sponset av maggiepoker.com" flourish; links out in a new tab.

#### `BottlePlaceholder.tsx`
An inline SVG bottle silhouette in the brand red, used for wines with no photo.

### State providers

#### `src/admin.tsx`
Admin mode, held in memory only — nothing is persisted, so a reload logs you out.

| Function | Purpose |
| --- | --- |
| `AdminProvider({ children })` | Holds the validated password and exposes `isAdmin`, `login`, `logout`. |
| `useAdmin()` | The hook every admin-gated UI reads; throws outside the provider. |

#### `src/i18n/index.tsx`
The locale registry and context.

| Function | Purpose |
| --- | --- |
| `I18nProvider({ children })` | Provides the active locale's strings (`nb` by default). |
| `useStrings()` | **The only supported way to read UI text.** Never hardcode text in JSX. |
| `useLocale()` | Current locale + setter, so a language switcher can be added without refactoring. |

#### `src/i18n/types.ts`
`LocaleStrings` — the interface describing every user-facing string, grouped by
section (`common`, `nav`, `payment`, `wheel`, `wines`, `stats`, `sponsor`, `admin`).
Some entries are functions (e.g. `stats.viewCollection(count)`,
`payment.amount(kroner)`) so plurals and units stay inside the locale. Adding a
language means one new file that TypeScript checks for completeness.

#### `src/i18n/locales/nb.ts`
`nb` — Norwegian bokmål, the default and currently only locale.

### Data access and shared types

#### `src/api.ts`
Every call to the backend, plus offline fallbacks so the UI always renders.

| Symbol | Purpose |
| --- | --- |
| `FALLBACK_WHEEL_NAMES`, `FALLBACK_WINES`, `FALLBACK_PLAYERS`, `FALLBACK_PAYMENT` | Local sample data used when a fetch fails. |
| `fetchJson(url, fallback)` | *(private)* GET + parse, logging and falling back on any error. |
| `fetchWheelNames()`, `fetchWines()`, `fetchPlayers()`, `fetchPayment()` | The four read endpoints. |
| `adminLogin(password)` | Validates a password; `true`/`false`. |
| `savePayment(settings, password)` | PUTs the Vipps amount/number; `null` on failure. |
| `WheelMutation` | `{ ok: true, names }` or `{ ok: false, reason: 'duplicate' \| 'failed' }`. |
| `mutateWheelNames(url, init)` | *(private)* Shared POST/DELETE handling that maps `409` to `duplicate`. |
| `addWheelName(name, password)` | Adds a participant (and their stats row). |
| `removeWheelName(name, password)` | Takes a participant off the wheel only. |
| `NewWineInput`, `AddWineResult` | The add-wine payload, and its result (`too-large` vs `failed`). |
| `addWine(input, password)` | Logs a wine, optionally with a base64 photo. |
| `recordSpin(winner, names, password)` | Records a spin result into the stats. |

#### `src/types.ts`
The domain types shared by the API layer and the UI: `Wine`, `PlayerStats`
(record + derived `collection`) and `PaymentSettings`. They mirror the server's
types deliberately — the client never imports from `server/`.

#### `src/images.ts`
`IMG` — the central map of decorative image URLs (`/img/…`). Swapping an image is
replacing the file at the same path.

#### `src/config/payment.ts`
`VIPPS_AMOUNT` / `VIPPS_NUMBER` (the `X`/`Y` placeholders shown until an admin sets
real values) and `VIPPS_APP_LINK` / `VIPPS_WEB_LINK` (where the payment box points
on touch vs. desktop).

#### `src/config/sponsor.ts`
`SPONSOR_URL` — where the sponsor tag links.

#### `src/vite-env.d.ts`
Vite's client type reference. No code.

### `src/styles.css`
The single stylesheet, in sections: `:root` tokens (wine red, grape, gold, cream,
`--nav-height`), header, layout, payment page, wheel page, wine list, stats page,
roster editing, modal, add-wine form, sponsor tag, bottom nav, and the responsive
blocks (≤900px, ≤768px, ≤480px).

Two conventions worth knowing:

- **Fluid scaling.** Sizes are written `clamp(<old fixed value>, <vw>, <max>)` with
  the middle term tuned so the value equals the original at ~1280px wide. Small and
  medium screens are unchanged; large monitors get proportionally bigger type,
  images and controls.
- **The pouring backdrop** (`.pour-bg`) is Betaling-only and mobile-only, anchored
  high in the right corner with `transform: translateX(32%)` — a percentage of the
  element's own width, because the image's width follows its height (`72vh`), so a
  pixel offset would hide a different slice of the bottle on every phone.
